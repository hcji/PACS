# Fig.1 系统可靠性实验

「同一套测量仪器，重复测量同一个对象，读数稳不稳」——这是 Fig.1 要回答的问题，也是下游结论（剂量-反应、特异性、分型）可信度的前提。

本页说明实验设计、四条比较轴、每个指标的口径与读法，以及引用这些数字时必须一并声明的局限。

## 1. 文件与角色

| 文件 | 作用 |
|---|---|
| `tools/fig1_reliability.py` | 实验矩阵驱动：跑四条轴，逐被试落盘，出汇总报告与面板数据 |
| `tools/reliability.py` | 可靠性统计（ICC / CV / SEM / Bland-Altman / κ / 方差分解），纯标准库 |
| `tools/fig1_dose_response.py` | 剂量-反应：把 θ 摆成完整度梯，判单调性、拟合斜率、分「可解释 / 需额外条件」 |
| `tools/fig1_export_table.py` | 导出人读表（CSV + XLSX）：一行一被试，附列说明与汇总表 |
| `results/scripts/fig1_viz_data.py` | 读发布表与面板数据，计算 Fig.1 各面板指标 |
| `results/scripts/fig1_visualize.py` | 绘图层：上排 2 块 + 下排 3 块 |

## 2. 四条轴

| 轴 | 变化的是什么 | 回答的问题 |
|---|---|---|
| ① 同一脑重复 | 什么都不变（只重跑） | 仪器本身的噪声有多大 |
| ② 不同 LLM | 模拟大脑换成另一个模型（提问者/分析者不变） | 换个「心智」实现，读数还可比吗 |
| ③ 不同 examiner / analyst / 题序 | 提问者、分析者、题目顺序 | 读数依赖谁在问、谁在判、按什么顺序问吗 |
| ④ 不同轮次 | 对话轮数（25 / 50 / 100） | 问多问少会改变结论吗 |

轴① 是共享参照臂：轴② 拿它当 A 模型那一半、轴③ 拿它当比较基准、轴④ 拿它当 50 轮档，因此重复次数最多（默认 5）。

### 2.1 剂量梯

四条轴共用一条 belief updating 完整度梯：

| 文件名序号 | θ | 完整度 | 说明 |
|---|---|---|---|
| 001 | `intact` | 1.00 | 完整心智基线 |
| 002 | `belief_updating:0.8` | 0.80 | 轻度削弱 |
| 003 | `belief_updating:0.4` | 0.40 | 中度削弱 |
| 004 | `belief_updating:0.3` | 0.30 | 重度削弱 |

**θ 是完整度，不是损伤度**：1.0 = 完整，0.8 比 0.4 更接近正常。「削弱越重 → 读数越低」在完整度轴上表现为曲线从左到右上升。

## 3. 轮次协议

| 轴 | `n_turns` | `max_turns` | 实际行为 |
|---|---|---|---|
| ①②③ | 50 | 100 | 跑满 50 个基础轮后，7 个计分通道配额（每通道 ≥5 问）都满足就收工；仍有缺口才补问，最多到 100 |
| ④ | L（25 / 50 / 100） | L（同值） | `run_limit = max_turns = L`，硬固定在 L 轮 |

题目集合：每个 `(seed, mode)` 生成一份 100 条清单，条件内所有被试复用；轮数按位置截断（第 i 轮用 `probe_items[i-1]`）。因此 L=25 用的正是 L=50 的前 25 题，形成嵌套结构，尽量把「轮数效应」与「题集效应」分开。

### 3.1 输出额度

真实 provider 请求里的 `max_tokens` 由 `config.json` 的 `llm.max_tokens` 决定，分析者另有 8000 的硬下限（`ANALYST_MIN_TOKENS`）。推理型模型会把额度先花在思维链上，正文被挤成空串时这次调用直接失败。

本实验统一使用：

```bash
--max-tokens 8000 --analyst-max-tokens 32768
```

模拟大脑与提问者用 8000；分析者单独给 32768（它要吐一整段 JSON：7 段逐维记录 + 约 350 字结论 + 判定依据）。`max_tokens` 与 `analyst_max_tokens` 都逐被试写进 `run_parameters`；`--resume` 的协议一致性守卫会比对轮数与额度。

## 4. 指标口径

方向约定：**读数 1.0 = 与同龄典型发展无异，0.0 = 严重偏离**。ICC 越高越可靠；CV / SEM / Bland-Altman 界限越小越可靠。

| 指标 | 口径 | 怎么读 |
|---|---|---|
| **ICC(2,1)** | 双向随机效应、单次测量、绝对一致性。`(MSR−MSE)/(MSR+(k−1)MSE+k(MSC−MSE)/n)` | 主数字。以 (θ × 维度) 单元格为目标（28 个目标 × 重复次数） |
| **ICC 区间** | 对目标留一的 jackknife | 21–28 目标 × 5 重复下实测覆盖 0.91–0.93（略偏窄）；目标数 < 10 时不给区间 |
| **SEM** | `√MSE`，与读数同单位 | 单次测量的典型误差，可直接与 0.15 这个「看得出区别」的尺度对比 |
| **SEM 区间** | `df·MSE/χ²(df)` 的精确 χ² 区间 | 任意目标数都成立，精度陈述优先引它 |
| **CV** | 目标内 标准差/均值 | 相对波动；均值接近 0 时不给 |
| **Bland-Altman** | 次与次配对的偏倚 ± 1.96·SD(差) | 偏倚≈0 说明没有系统性漂移；界限宽度即偶然误差 |
| **剖面相关** | 按次（列）两两相关，Pearson + Spearman | 整体形状能不能复现；与 ICC 互补 |
| **排序稳定度** | 维度高低顺序在次间的一致度 | 同样的互补视角，只看序不看值 |
| **落在容差内** | 两次测量 \|Δ\| ≤ 0.15 的比例 | 最直观的「能不能当成同一个数」 |
| **档位 κ** | `asd_likeness`（none/mild/moderate/marked）的 Cohen's κ（含线性加权） | 结论级可靠性的主指标 |
| **结论 Jaccard** | 结论文本的字符 n-gram Jaccard | 辅助；词汇层近似，不是语义相似度 |
| **自造题率** | 提问者没用上条目库条目的轮次比例 | 题序轴与轮次轴的共变量，必须一起报 |
| **未覆盖通道** | 一个问题都没问到的通道 | 这些维度的读数不作为「无异常」证据 |

### 4.1 为什么 ICC 主数字用「(θ × 维度) 单元格」

目标数从 3 个 θ 涨到 21–28 个单元格，区间才有意义。3 个目标的 ICC 置信区间宽到没有信息量，因此 `reliability.ICC_CI_MIN_TARGETS = 10` 会拒绝给出区间——宁可不说，也不给一个名不副实的区间。逐维度 ICC 仍照报，但那只是点估计。

### 4.2 剂量-反应

`fig1_dose_response.py` 以完整度为横轴（1.00 / 0.80 / 0.40 / 0.30），逐档给读数均值、偏离（1 − 读数）与均值的标准误，并判断「削弱越重 → 读数越低」是否成立。三条口径：

1. **主结果只用参考臂**（同脑、同提问者、同分析者、同题序、同轮数，唯一变量是 θ）。轴② 换了脑、轴③ 换了提问者/分析者/题序、轴④ 换了轮数——这些条件下读数同时受 θ 效应与该轴效应影响，混进同一条梯子后出现非单调就无法归因。
2. **每档均值的精度按被试算**：`SE = SD(被试内均值) / √n`，相邻两档的判据是 `|Δ| > 2×SE(Δ)`，`SE(Δ) ≈ √(SE₁² + SE₂²)`。不能拿单次读数的 SD 或 cell SEM 当尺子。
3. **分开「可解释」与「需额外条件才能归因」**：方向（单调性、ρ、拟合 R²）由参考臂单独就能定下来；档间差落在 2SE 里、或只在混了别的轴的条件下出现，就必须写成需额外条件才能归因。

## 5. 单元格级重试与续跑

真实端点会间歇性超时、5xx 或返回空响应。`run_design` 的契约是「遇到 `LLMError` 记进 `failures` 然后跳过整条被试」，而下游 `matrix_from_records` 只保留测量次数达到最多的目标——一个坏掉的 (θ, 重复) 单元格会让整组目标被静默丢弃。

驱动因此按单元格组织运行：

- **一轮 = 所有 θ 各测一次**，对应一个 `replicate` 编号；一轮内失败的 θ 在本轮内重试，最多 `CELL_ATTEMPTS = 3` 次，仍失败才记进 `failures` 并在最终报告里单独打印。
- **重复号由驱动自己打**，不用 `run_design` 内建的 replicate 计数：后者把「第几次出现」当重复序号，一旦某次尝试失败后重跑，序号就会错位、覆盖已落盘的文件。
- **一次 `run_design` 只放一个 design**：会话只能从 `on_dialogue(session, feedback)` 拿到，而这个回调不带 θ 标识；一批多个 design 时配对会静默错位。
- **「调用成功但产出残缺」也算失败**，判据有四条：`parse_error` 非空、一个维度读数都没有、结论为空、档位判定缺失。刻意不要求「7 维全部有值」：轮数少时本来就有通道探查不到，分析者对这些通道给 `None` 是合法结果。
- **`--resume` 精确到单元格**：先扫 `subjects/`，把已落盘且协议一致（同 `condition_id`、同 `n_turns` / `max_turns` / `max_tokens`、且真的有读数）的单元格读回来当作已完成，只补缺失的那些。

## 6. 用法

```bash
# 1) 先看矩阵与成本（不调用模型）
python tools/fig1_reliability.py --dry-run

# 2) 离线跑通管线（Mock，秒级）
python tools/fig1_reliability.py --provider mock --mini

# 3) 真实批量：建议先跑单条件验证，再放开全矩阵
python tools/fig1_reliability.py --conditions axis1_same_brain \
    --thetas "intact,belief_updating:0.3" --replicates 2 --yes
python tools/fig1_reliability.py --model-a deepseek-flash --model-b deepseek-v4-pro --yes

# 3b) 中断后续跑：按单元格补齐，已完成的被试不会重跑
python tools/fig1_reliability.py --model-a deepseek-flash --model-b deepseek-v4-pro \
    --out data/runs/fig1_main --resume --yes

# 4) 剂量-反应（读已落盘的产物，不调用模型）
python tools/fig1_dose_response.py

# 5) 导出人读表（一行一被试；CSV + XLSX）
python tools/fig1_export_table.py
```

## 7. 规模与成本

默认全矩阵 87 被试（3 θ），预计调用 9,537（基础轮）～15,237（上界）。补成 4 档剂量梯后为 116 被试，预计调用 12,716～20,316。

| 条件 | 轴 | 轮次 | 重复 | 3 θ 时被试 | 4 θ 时被试 |
|---|---|---|---|---|---|
| `axis1_same_brain` | ① | 50/100 | 5 | 15 | 20 |
| `axis2_brain_pro` | ② | 50/100 | 5 | 15 | 20 |
| `axis3_examiner_pro` | ③ | 50/100 | 3 | 9 | 12 |
| `axis3_analyst_pro` | ③ | 50/100 | 3 | 9 | 12 |
| `axis3_probe_seed7` | ③ | 50/100 | 3 | 9 | 12 |
| `axis4_turns_25` | ④ | 25/25 | 5 | 15 | 20 |
| `axis4_turns_100` | ④ | 100/100 | 5 | 15 | 20 |
| **合计** | | | | **87** | **116** |

支持 `--resume` 跳过已完成条件、`--axes` / `--conditions` 选跑、`--mini` 缩微矩阵干跑。并行分片时用 `--no-report` 避免多个进程抢同一个文件，跑完再用不带该参数的一次 `--resume` 汇总。

实测耗时（DeepSeek 端点）：真实对话调用约 4.2 s/次（长提示词 + 分析者 8k token 级输出）。据此推算：单条件验证（3 θ × 2 重复，8 轮）约 12 分钟；单条件真实协议（3 θ × 5 重复，50/100 轮）约 1.8 小时；全矩阵约 11–18 小时。

## 8. 引用时必须声明的局限

1. **Mock 不是证据**：mock provider 的可靠性恒为 1，验证的是管线，不是 LLM 涌现行为。
2. **真实运行没有 seed 可用**：provider 请求只发 model / messages / temperature / max_tokens，不发送 seed，temperature 固定取配置值（默认 0.3）。轴① 测的是服务端采样噪声。
3. **轴④ 的 L=25 低于配额下限**（7 通道 × 5 问 = 35）：该条件下必然出现 `under_quota_channels`，那些维度的读数是分析者按提示词给出的保守中性值，必须与 50 / 100 档分开表述。
4. **题集与轮数耦合已被缓解但未消除**：所有条件复用同一份清单、轮数按位置截断，使 L=25 用的正是 L=50 的前 25 题；但提问者自造题的轮次会打破严格嵌套。诊断表里给出「自造题率」供核对。
5. **轴③ 的 seed 只改变第 7 位起的题序**：`dialogue_probes` 的前 6 位由目标通道确定性选出，对任何 seed 都相同；观察提纲对所有 seed 完全一致。
6. **ICC 区间的实际覆盖率略低于名义值**：多目标形状下 jackknife 实测 0.91–0.93（而非 0.95），且目标数 < 10 时不给区间。精度陈述应优先引用 SEM 的精确 χ² 区间。
7. **逐维度 ICC 只有 3–4 个目标**，点估计可用但不可给区间，也不应据此排名单个维度。
8. **结论级相似度是词汇层近似**：字符 n-gram Jaccard 衡量用词与句式；意思相同但措辞不同的结论会被判为低相似。结论级可靠性的主指标应看 `asd_likeness` 档位一致度（κ 与完全一致率）。
9. **50/100 协议下实际轮数可变**：配额未满会补问，因此同一条件的 `n_turns_run` 并不恒定。报告时不能只说「跑了 50 轮」。
10. **本实验不写入项目数据库**：产物全在文件系统，`pacs analyze` / `pacs report` 看不到这批数据。
11. **单元格级重试仍可能耗尽**：重试上限为 3 次，超过就放弃那一格。报告里的 n 是实际入矩阵的目标数，`cell_failures` 字段逐个列出缺失的 (θ, 重复)。引用任何 ICC 时都应同时给出 n。
12. **分析者可以合法地对单一维留 `null`**：该格会被剔出 ICC 而不补值，并在报告里单列说明，该条件的 cell 目标数也随之少一个。
13. **剂量梯的细档在现有样本量下分不开**：参考臂每档 n=5，「削弱有影响」可以确认（各削弱档与完整档的差都超过 2SE），但 0.80 / 0.40 / 0.30 三档彼此之间的差多数不超过 2SE，不能凭这份数据排序。
14. **一条梯子被压缩不等于剂量效应消失**：轴②（换脑）的整梯落差只有参考臂的约 1/5。「换脑」与「削弱剂量」在读数上部分重合，因此该臂不宜用来估计剂量效应的大小。

## 9. 论文里怎么读这些数

- **主图（Fig.1）**：每个轴一张表/一组点，纵轴是 ICC 与 SEM，横轴是条件。轴④ 天然是一条「可靠性 vs 轮数」的曲线。
- **正文一句话**：在 N 个 (θ × 维度) 单元格上重复 k 次，ICC(2,1) = X（jackknife 区间 [A, B]，该规模下实测覆盖率 0.91–0.93），SEM = Y（精确 95% χ² 区间 [C, D]），档位完全一致率 = Z。
- **不要**用 mock 运行的数字下任何关于 LLM 的结论。
- **不要**把轴③ 的 seed 条件描述成「改了整个题集」——它只改了第 7 位起的题序。
- **不要**把逐维度 ICC 的排序当成发现——那只有 θ 数个目标、没有区间。
- **剂量-反应**可以写成：参考臂上按完整度 1.00 / 0.80 / 0.40 / 0.30 的读数均值为 0.899 / 0.682 / 0.598 / 0.516，严格单调，拟合 `读数 ≈ 0.380 + 0.471 × 完整度`（R² = 0.892）；各削弱档相对完整档的偏离均超过 2SE。但不要据此宣称三档彼此可分，也不要用轴② 的落差去估计剂量效应大小。
- **对削弱最敏感的维度**是「认知灵活性与适应」，其次是「重复性与限制性行为」；对照通道「一般认知控制」落差最小。这是特异性证据，但它是单条剂量梯上的读数，不是诊断结论。
